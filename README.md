## What is LUCA?

**LUCA** (LLM-based Unified Corporate Analyst) is a multi-agent pipeline that turns regulatory financial filings, starting with SEC 10-K filings, into structured, verifiable financial data. The design is hybrid: quantitative figures are extracted programmatically from the filing's XBRL data, while a language model handles qualitative text such as risk factors. Numbers are never generated by the LLM.

Developed as an **AI Lab** project (2025-2026) at **Universidad Pontificia Comillas (ICAI-ICADE)**, Mathematical Engineering and Artificial Intelligence program.

### Key characteristics

- **Hybrid extraction**: structured XBRL facts for financial metrics, LLM only for qualitative text
- **Deterministic numbers**: the quantitative extractor is rule-based and reproducible, with no sampling variance
- **Traceability by design**: every extracted figure maps back to its source in the filing
- **Local LLM**: the qualitative layer runs a quantized 7B model on a consumer GPU (8 GB VRAM)
- **Automated tests**: 240 tests, fully mocked and offline

---

## Pipeline overview

LUCA is organized as a sequence of specialized agents:

| Stage | Role |
|-------|------|
| **Ingestion** | Retrieves 10-K filings and XBRL data from SEC EDGAR |
| **Parsing and chunking** | Splits the filing into sections, isolating the risk factor item for the qualitative layer |
| **Structured extraction** | Extracts core financial metrics (revenue, net income, operating income, total assets, total equity, diluted EPS) directly from XBRL |
| **Qualitative extraction** | LLM-based extraction and classification of risk factors from the filing text |
| **Derived metrics** | Deterministic computation of ratios and derived figures |
| **Report generation** | Assembles the structured output into an analyst-style memo |

---

## Validation

The structured extractor was validated against a hand-annotated gold standard of core financial metrics, with numeric comparison at 0.5 percent relative tolerance:

- **XBRL structured extraction: 100 percent accuracy.** The extractor is deterministic, so this result has no sampling variance.
- On the same items, LLM-only baselines reached about 50 percent (structured prompting) and 3.3 percent (naive prompting), which motivates the hybrid design: XBRL for numbers, LLM for text.

---

## Traceability

Traceability is the design priority. Every extracted figure maps back to its source in the filing: the pipeline records where each value came from, so any number in the output can be checked against the original document. This matters in financial contexts, where an unverifiable number is a liability rather than an asset.
